# Translations (i18n) — how to add or finish a language

Read this before translating. Status at any time: `python scripts/i18n_tool.py status`.

## Where text lives

| What | Where | Languages |
|---|---|---|
| UI strings, core | `app/i18n.py` → `TRANSLATIONS` (inline) | de, en, fr, it, pt — complete (626 keys) |
| UI strings, added languages | `app/locales/<lang>.json` (flat `{key: text}`), merged at startup by `app/i18n_locales.py` | zh, ko, ro — 0% (as of 2026-09-26) |
| Transactional e-mails | `app/email_localization.py` (one copy dict per e-mail function) + `EMAIL_LANGUAGES` | de, en, fr, it, pt; others fall back to English |
| Admin / God Mode / Red Zone UI | `t_en()` — **always English**, by design | — do not translate |

A key missing from a locale file falls back to English, so a language can go live partly translated (zh/ko/ro are already in the picker, showing English).

## Workflow — translate in batches (token-cheap)

```bash
python scripts/i18n_tool.py todo zh --limit 80 --out zh_batch.json   # next 80 missing keys (en + de context)
# fill every "translation" field in zh_batch.json (keep the file OUT of the repo)
python scripts/i18n_tool.py apply zh zh_batch.json                    # validates + merges into app/locales/zh.json
python scripts/i18n_tool.py status                                    # coverage
scripts/test_in_docker.sh tests/test_i18n_locales.py                  # guards
```

`apply` rejects (and reports) unknown keys, empty text and any `{placeholder}` mismatch with English — e.g. `{name}`, `{amount}`, `{days}` must appear exactly as in English, untranslated. Re-running `todo` only lists what is still missing. For an AI session: one batch per step, apply, repeat; don't open `app/i18n.py` (170 KB) — the batch file has all the context needed.

## Translation rules

- Translate **meaning for a musician audience**, not word by word. Many strings are short button labels without context; the German (`de`) column is the original product voice — use it to disambiguate.
- Keep length close to the English; mobile buttons are narrow.
- Tone: informal, like German `du` / Portuguese `você`. Proposed for new languages (confirm with Daniel): zh 你 (not 您), ko polite 해요체, ro informal `tu`.
- Keep HTML tags and `{placeholders}` intact; don't add punctuation the source doesn't have.

## Adding a brand-new language (e.g. es)

1. `app/i18n.py`: add the code to `SUPPORTED_LANGUAGES` and a flag/label to `LANGUAGE_META` (shows it in the picker).
2. Create `app/locales/<code>.json` containing `{}` — `test_every_non_core_language_has_a_locale_file` enforces this.
3. Translate with the workflow above.
4. E-mails (optional, when ready): add the language's copy to **every** function in `app/email_localization.py`, then add the code to `EMAIL_LANGUAGES`. `test_every_email_template_covers_every_email_language` fails if any function is missing it.
5. CJK only: `brand.css` has `:lang(zh)` / `:lang(ko)` system-font fallbacks, but no bundled CJK font yet (Manrope has no CJK glyphs) — rendering varies by device. Bundling a licensed font (e.g. Noto Sans SC/KR, OFL) is an open item.

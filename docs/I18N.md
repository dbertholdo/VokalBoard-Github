## Workflow — phase 2 in batches (token-cheap)

```bash
python scripts/i18n_tool.py todo es --limit 80 --out es_batch.json   # next 80 missing PUBLIC keys (en + de context)
# fill every "translation" field (batch files are gitignored)
python scripts/i18n_tool.py apply es es_batch.json                    # validates + merges into app/locales/es.json
python scripts/i18n_tool.py status
scripts/test_in_docker.sh tests/test_i18n_locales.py
```

`apply` rejects (and reports) unknown keys, empty text, admin-only keys and any `{placeholder}` mismatch with English — `{name}`, `{amount}`, `{days}`… must stay exactly as in English. `todo` only lists public keys still missing. For an AI session: one batch per step, apply, repeat; never open `app/i18n.py` (170 KB) — the batch file carries the context.

## Translation rules

- Translate **meaning for musicians**, not word by word. Many strings are short button labels; the German (`de`) column is the original product voice — use it to disambiguate.
- Keep length close to English — mobile buttons are narrow.
- **Tone: common, modern, informal** (like German `du` / Portuguese `você`): es `tú`, ro `tu`, zh `你` (not `您`), ko polite-informal 해요체.
- Keep HTML tags and `{placeholders}` intact; don't add punctuation the source doesn't have.

## Adding yet another language later

1. `app/i18n.py`: add the code to `SUPPORTED_LANGUAGES` and a flag/label to `LANGUAGE_META` (+ `flag_img`: download the SVG, see `app/static/img/flags/MANIFEST.md`); add it to `_STRIPE_LOCALES` in `app/notas_purchase.py` if Stripe supports it.
2. Create `app/locales/<code>.json` with `{}` (a test enforces it).
3. Follow the route above. Admin stays English automatically.
